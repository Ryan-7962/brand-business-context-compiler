# 读取质量验收 Playbook｜PDF / PPT / 长图

## 1. 目的

这份 playbook 用来判断第一阶段 Source-to-Markdown 是否已经“够用”，以及什么时候需要换 MarkItDown、MinerU、截图复核或人工补录。

这里的“够用”不是摘要写得顺，而是后续 `outputs/` 和 `brand_context_library/` 能基于可追溯的转写结果工作：

- 文件、页码 / slide、来源锚点没有漏。
- 关键文字、表格、图片 / 图表、小字和脚注的读取状态被明确标出来。
- 低置信度页面不会被当成已读事实。
- 需要人工介入的内容只进入 exception review，不要求用户逐条检查全部事实表。

本 playbook 只服务第一阶段，不负责选择一套通用 OCR 平台，也不把 MarkItDown / MinerU 当作品牌知识编译器。

## 2. 验收输入

验收前至少应有这些材料：

- `converted_markdown/source_transcripts/`
- `converted_markdown/conversion_report.md`
- `converted_markdown/source_quality_report.md`
- 原始文件的页数 / slide 数线索
- 对应页面截图或导出的 slide / 长图截图

如果还没有 `source_quality_report.md`，先运行 source conversion 和质量报告生成；不要直接根据最终摘要判断读取质量。

## 3. “够用”的最低标准

一份资料可以进入后续编译，必须同时满足：

| 项目 | 够用标准 |
|---|---|
| 覆盖范围 | 总页数 / slide 数、已读取范围和缺失范围一致；没有静默跳过文件或页面。 |
| 来源锚点 | 每页 / slide 至少能回到 `Source ID + page/slide`，关键事实能回到具体 anchor。 |
| 正文文字 | 标题、分节、主文案、卖点、策略动作、数字和限制条件没有明显漏读。 |
| 阅读顺序 | 多栏、图文混排、流程图的顺序不影响理解核心结论。 |
| 表格 | 表头、行列关系、单位、脚注能读懂；不能还原的表格被标成待复核。 |
| 图片 / 图表 | 视觉页有截图或 asset 占位；图中关键文字、数值、标签未读清时有低置信度标记。 |
| 小字 / 脚注 | 限制条件、免责声明、价格 / 时间 / 渠道范围等小字没有被默认忽略。 |
| 低置信度 | 低文字量、OCR 风险、表格风险、图片风险已经进入 review queue 或质量报告建议动作。 |

不满足这些标准时，不能把后续 `source_facts`、语义转述或资产索引当成完整读取结果。

## 4. 必须抽样的页面

抽样不是随机看几页，而是优先看最容易误读、最影响后续 Wiki 的页面。

每份 PDF / PPT 至少抽：

1. 封面和目录页：确认文件主题、版本、日期、章节结构是否识别正确。
2. 第一页正文和最后一页正文：确认开头、结论、附录或联系方式没有被漏读。
3. 每个章节的第一页：确认大纲和层级没有跑偏。
4. 所有低文字量但有大量视觉元素的页面：常见为纯图、海报、包装图、流程图、KV、长图切片。
5. 所有表格页：尤其是价格、SKU、渠道政策、检测结果、投放数据、达人 / 内容复盘表。
6. 所有包含小字、脚注、角标、免责声明、适用范围的页面。
7. 所有 `source_quality_report.md` 标记为低置信度、需 OCR、需表格复核、需人工复核的页面。
8. 多版本资料中疑似同主题但更新时间不同的关键页。

如果资料少于 10 页，全部抽样。超过 10 页时，除上述必抽页面外，再补 2-3 页普通正文页，用来确认 baseline 转写不是只在异常页失效。

## 5. 不同来源类型的重点

### 5.1 PDF

PDF baseline 可以先用当前轻量链路。验收重点：

- 文本型 PDF：看页码、标题层级、段落顺序、表格和脚注。
- 扫描型 PDF：看 OCR 是否实际发生；如果转写文字很少但截图信息丰富，不能视为已读。
- 图文混排 PDF：看图片中的文字、图表标题、角标和流程箭头顺序。

PDF 只要关键内容主要来自截图 / 图像，优先按视觉资料处理。

### 5.2 PPT / PPTX

当前轻量路径只抽 slide 文本，不保留完整排版、图片、图表、动画和备注。验收重点：

- slide 数是否完整。
- 每页标题、主文案、图中文字和 speaker notes 是否缺失。
- 左右对比、四象限、流程箭头、图例和标签是否被打乱。
- 关键策略页、卖点页、执行排期页、预算 / 数据页是否需要截图补充。

如果 PPT 的核心信息在图、图表或版式关系里，只靠轻量 PPTX 文本抽取不够。

### 5.3 长图 / 截图

长图、详情页截图、检测报告截图和竞品截图应默认高风险。验收重点：

- 是否被切分或缩放到可读。
- 标题、模块分隔、图中文字、表格、脚注、角标是否可追溯。
- 是否保留原图或截图锚点。
- OCR 读不出的区域是否进入人工补录。

长图不能因为生成了一段 Markdown 就默认通过；必须看关键区域截图和 OCR 覆盖。

## 6. 低置信度处理

低置信度不是失败状态，而是禁止后续链路把不确定内容当作事实。

### 6.1 低置信度触发条件

出现以下任一情况，应标记低置信度：

- 页面有截图内容但提取文字很少。
- 表格被压成散乱文本，行列关系不清。
- 图表、流程图、四象限、对比图的阅读顺序不确定。
- 小字、脚注、角标、免责声明看不清或未出现在 transcript。
- 关键数字、单位、时间、价格、渠道范围缺来源锚点。
- PPT slide 只抽到标题，正文来自图片或图表。
- MarkItDown 输出缺稳定页码 / slide 边界。
- 同一主题多版本资料出现冲突。

### 6.2 处理原则

- 能定位到页面但读不清：保留页面 anchor，进入 review queue。
- 能看出资料没有提供：写 `待补充`，不要推断。
- AI 只能根据上下文猜测：写 `AI 结构化转述，待确认` 或 `AI 初步拟定，待品牌确认`。
- 关键事实低置信度：不要提升为长期库 confirmed 知识。
- 低置信度集中在少数页面：优先截图复核或人工补录，不必替换整套引擎。
- 低置信度覆盖整份文件：再评估 MarkItDown / MinerU。

## 7. 什么时候换引擎

工具切换的目标是减少漏读和人工复核成本，不是追求最强 OCR。

| 情况 | 默认动作 |
|---|---|
| 普通文本 PDF，页码稳定，表格少 | 继续用默认轻量链路。 |
| PDF 文本正常，但 Markdown 可读性差 | 可小样对比 MarkItDown。 |
| PPTX / DOCX / XLSX / HTML / ZIP 等多格式资料 | 优先小样评估 MarkItDown。 |
| PPTX 核心信息在图片、图表、版式关系里 | 导出截图抽样；必要时评估 MinerU 或人工补录关键页。 |
| 扫描 PDF、长图、截图、检测报告图像 | 优先截图 / OCR / MinerU 小样，不要只看 baseline Markdown。 |
| 表格、图片中文字、阅读顺序经常错 | 评估 MinerU；只在明显降低复核成本时接入。 |
| 只有 1-3 个关键页读不清 | 截图复核或人工补录，通常不要为了少数页面换全流程。 |
| 关键品牌口径、价格、策略判断冲突 | 不靠换引擎解决，进入版本 / 冲突 review。 |

MarkItDown 和 MinerU 都只是 Source-to-Markdown 候选。即使用它们转写，也仍需生成同一套 transcript、conversion report、quality report 和 source anchors。

## 8. 什么时候人工补录

人工补录适合小范围、关键、高风险内容：

- 图片中的一句核心卖点或限制条件。
- 表格中少量关键数值、单位或适用范围。
- 包装图、海报、长图中 OCR 无法稳定识别的区域。
- 需要业务判断的新旧版本冲突。
- 资料本身没有写明、只能由业务人员补充的信息。

人工补录应写清：

- 来源文件和页面 / slide / 图片区域。
- 补录的是原文、客观描述，还是业务确认。
- 是否可进入长期库。

人工补录不能把 AI 猜测伪装成来源事实。

## 9. 验收记录模板

可在质量报告或 review note 中按这个格式记录：

```markdown
## Source Reading QA

- Source ID：
- 文件类型：
- 总页数 / slide 数：
- 已抽样页面：
- 必抽页面是否覆盖：
- 关键风险：无 / 表格 / 图片 / 小字 / OCR / 阅读顺序 / 多版本冲突
- 当前结论：通过 / 条件通过 / 不通过
- 建议动作：继续 baseline / MarkItDown 小样 / MinerU 小样 / 截图复核 / 人工补录
- 不进入后续事实层的内容：
```

结论含义：

- `通过`：可进入后续编译，无关键读取缺口。
- `条件通过`：可进入后续编译，但指定页面或字段必须保留低置信度和 review queue。
- `不通过`：关键页面、页数、表格、图片或 OCR 大面积失效，先修 source conversion。

## 10. 验收完成标准

一次第一阶段验收完成，应能回答：

1. 这批资料读了哪些文件，是否有文件或页面漏读？
2. 哪些页面 / slide 被抽样，为什么抽这些？
3. 哪些低置信度内容不能作为来源事实？
4. 哪些问题用截图或人工补录解决，哪些需要 MarkItDown / MinerU 小样？
5. 后续 `outputs/00_source_index.md`、`10_context_asset_index.md` 和 `11_context_library_update_plan.md` 是否能基于这些读取结果继续工作？

只要以上问题答不清，就不要把问题交给后面的 Marketing Semantic Compiler prompt 去猜。
