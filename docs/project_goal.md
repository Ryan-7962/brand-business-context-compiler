# Project Goal｜Brand / Business Context Compiler

更新日期：2026-10-03。需求主文档：[完整PRD](../01_PRD_Brand_Product_Knowledge_Compiler.md)。

## 1. 最终目标

把品牌、产品、上市营销、GTM、渠道销售、会议、提案、复盘、竞品与检测等给人看的资料，完整转译为结构清楚、可追溯的Markdown；需要长期积累时，再组织成相互关联、可检索、可持续更新的Wiki。

默认单次转译：文件 → 完整读取与校准 → `compiled/<source-id>.md`（或用户指定路径）。一份或一批资料都可单次交付，不强制建库、长期索引或HTML。明确要求知识库/持续更新时，才启用下述Wiki架构，并复用现有证据。

单次模式完成盘点、转写和语义组织即可。建库模式中，Skill再做关联和索引；AI后续制作达人/KOC、培训、设计、渠道或GEO Brief时，先找知识，再读有关区段，必要时回源，不默认从零重读整套PDF/PPT。

不是普通摘要、文件格式转换、正式Web App、企业级RAG或自动投放系统。GEO是起点和验收场景，不是所有知识的固定分类，也不保证外部AI平台引用或投放效果。

## 2. 持续建库的三层架构

```text
Raw Sources
→ 保真转写与AI语义编译
→ Structured Wiki（文件知识 + 主题关联 + 任务索引）
→ Codex / WorkBuddy按需读取、引用、生成工作产出
```

原件保留，创建/修改时间与哈希记录；时间只是版本线索，不盲覆盖旧知识。
Wiki既能回答每份文件讲什么，也能回答某产品/项目关联哪些事实、策略、证据和复盘。
工作产出与知识事实分开，创意/建议不自动写回为事实，供应商不默认获得内部全库。

## 3. 最小交付

- 可移植Skill指令组包和必要本地工具。
- 来源转写、页/slide证据与真实读取状态。
- 单次模式：每份资料的详细结构化MD，含概述、大纲、正文、来源和真实异常，不止摘要。
- 建库模式：wiki/00_index.md、documents/知识页、uncertainties.md和中文本地概览。
- 由实际样本证明必要的少量主题页与相对链接，而非固定九类目录和每事实一文件。
- Codex为当前主环境，WorkBuddy为重点办公兼容目标；Markdown跨Agent，Obsidian可选。

历史outputs/和brand_context_library/保留兼容，不要求新项目跑两套架构或十余份默认产物。
不新增平台、向量数据库、复杂模型编排、自动外发或品牌审批。

## 4. 必须遵守

- 建库时完整盘点和读取；使用时按索引定位，证据不足扩大搜索或回源。
- 不静默漏页，不把截图生成、模型返回或结构校验等同内容准确。
- 保留产品/香型/配方、年份、单位、样本与条件，避免宣称跨范围泛化。
- 未读、读不清、来源缺失、来源不同与AI归纳分别标注，不冒充品牌确认。
- 分类灵活、关联有依据、链接真实存在；不知道的关系不编造。
- 重复导入复用有效证据；修订保留旧版本与原因，不破坏旧结果。
- 人只处理Agent补读后仍影响使用的真实异常，不逐条批准全部Markdown。
- 原件不修改；私有样本不进发布包；不自动上传或外发。
- 分享按任务选择内容，尊重当前/过往公司资料的授权边界。
- 不预设Wiki优于直接读取，未实测不报准确率、召回率或整体节省。

## 5. 验收

单次交付只要求来源覆盖、内容保真、可用MD及工程/隐私边界；以下关联、检索和更新项用于建库模式，不得以缺少Wiki阻止单次交付。

- 来源覆盖：支持文件全登记，页/slide数量可核对，未读范围真实记录。
- 内容：预登记关键事实和条件，与原页核对遗漏、错误与无依据陈述。
- 关联：多文件产品/项目/证据关系可核对，链接有效，无错误实体合并。
- 检索：固定问题集找到必需区段，多来源条件齐全，缺证据时说明未知。
- 更新：二次导入变化可定位，未改内容复用，冲突不静默覆盖，旧链接有效。
- 使用：真实Codex调用和WorkBuddy安装/调用；一次实际Brief与分享边界验证。
- 工程：测试、契约、失败保护、隐私与密钥检查通过，Git记录清楚。

多文件、多版本任务对照采用同模型、同资料、隔离会话，记录遗漏/错误、追溯、版本处理、读取范围、人工修正与包含首次编译的总成本。

## 7. 下一步顺序

多文件单次与本机宿主Skill调用已验证，原PDF到详细MD及MD派生brief取得有限验收证据。下一步优先Windows办公试用反馈或PPTX原件隐藏页/备注测试，不重跑已成功样本、不扩大功能。长期建库按需继续：

1. 用现有私有转写做最小关联Wiki样本，不全量重编、不新建平台。
2. 预登记消费者问法、香型限定、多来源证据、版本与未知问题，WorkBuddy执行、Codex核验。
3. 用修订材料验收增量更新与稳定链接。
4. 完成Windows/WorkBuddy实际安装及一个Brief/任务资料包验收。

每轮优先关闭真实检索、事实或使用断点。无证据的新功能跳过；阻塞时报告尝试、证据、缺口与所需输入，不虚报完成。
