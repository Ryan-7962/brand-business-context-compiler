# Quality Sampling Protocol｜Structured Wiki 读取准确度抽样协议

本协议用于补足 `docs/phase1_completion_audit.md` 中提到的 90% 准确性证据缺口。它不要求人工逐条复核全部 Wiki 内容，而是用可复现的抽样记录证明：Structured Wiki 对来源资料的读取、转写、结构化和风险暴露达到可接受水平。

## 1. 适用范围

本协议验证以下链路：

```text
Raw Sources
→ converted_markdown/source_transcripts/
→ converted_markdown/source_facts/
→ outputs/00-11
→ brand_context_library/
```

抽样对象是来源资料中的页面、slide、表格、图片说明、小字区域、OCR 区域、关键事实和最终 Wiki 条目。抽样过程只记录文件名、页码、字段类型、问题类型、是否通过和修正建议，不复制真实品牌原文、价格、预算、销量、渠道政策或未公开策略内容到正式文档。

## 2. 抽样页选择规则

每个资料包先生成 `source_quality_report.md`、`00_source_index.md`、`10_context_asset_index.md` 和 `11_context_library_update_plan.md`，再抽样。抽样必须覆盖以下页面类型：

| 类型 | 选择规则 | 目的 |
|---|---|---|
| 普通正文页 | 随机选择 2-3 页 | 验证常规阅读顺序和事实提取 |
| 首页 / 目录 / 总结页 | 每个文件至少 1 页，如存在 | 验证文件画像和大纲是否跑偏 |
| 高密度表格页 | 每个资料包至少 2 页；不足则全选 | 验证表格行、列名、单位和备注是否保留 |
| 图片 / 图表 / 截图页 | 每个资料包至少 2 页；不足则全选 | 验证视觉信息是否被识别或正确标为低置信度 |
| 小字 / 脚注 / 角标页 | 每个资料包至少 1 页；不足则全选 | 验证风险、限制条件、适用范围是否丢失 |
| OCR / 扫描 / 长图页 | 每个资料包至少 2 页；不足则全选 | 验证 OCR 可读性和漏读暴露 |
| 低置信度页 | 从质量报告中优先抽 30%-50% | 验证系统是否诚实暴露问题 |
| 关键业务结论页 | 每个资料包至少 2 页 | 验证后续 Wiki 是否引用了正确依据 |
| 多版本 / 冲突线索页 | 如存在则全选 | 验证版本判断不靠猜测 |

如果同一页同时属于多种类型，只记为一个抽样页，但在记录中勾选全部风险类型。

## 3. 抽样数量建议

按资料包总页数或总 slide 数决定最小抽样量：

| 资料包规模 | 最小抽样量 | 强制要求 |
|---|---:|---|
| 1-20 页 | 至少 6 页，或全量的 30%，取较大值 | 覆盖所有低置信度页 |
| 21-80 页 | 至少 12 页，或全量的 20%，取较大值 | 低置信度页不少于 4 页 |
| 81-200 页 | 至少 20 页，或全量的 12%，取较大值 | 高风险页不少于抽样量的 40% |
| 200 页以上 | 至少 30 页，或全量的 8%，取较大值 | 分文件、分类型抽样 |

额外规则：

- 每个源文件至少抽 2 页；只有 1 页的文件全量抽。
- 每个资料包至少抽 5 条已经进入 `brand_context_library/` 的 Wiki 条目，验证其来源锚点和信息状态。
- 每个资料包至少抽 5 条 `source_facts/` 事实候选，验证它们是否只来自来源资料。
- 如果系统声称达到 90% 准确性，抽样中必须包含失败风险最高的页面，而不是只抽普通正文页。

## 4. 记录字段

建议在私有测试目录中为每次验收建立 `quality_sampling_log.md` 或表格。正式仓库文档只保留匿名汇总，不保留私有原文。

| 字段 | 说明 |
|---|---|
| run_id | 本次资料包或验收批次 ID |
| source_file_id | 可匿名化的文件 ID，不写真实敏感文件名 |
| page_or_slide | 页码、slide 编号或 anchor |
| sampled_reason | 随机、表格、图片、小字、OCR、低置信度、关键结论、多版本等 |
| source_anchor | 对应 transcript / source facts / output / library 条目路径和锚点 |
| expected_source_state | 人工查看来源后确认的状态：清晰、部分清晰、不可读、资料未提供 |
| wiki_claim_type | 正文转写、事实候选、策略结构、风险项、长期库条目、检索提示等 |
| accuracy_result | 通过、不通过、部分通过、无法判断 |
| issue_type | 漏读、错读、顺序错误、表格结构丢失、图片未标注、小字遗漏、OCR 错误、编造、版本混淆、来源缺失 |
| severity | P0、P1、P2、P3 |
| correction_needed | 需要重新 OCR、换引擎、人工补录、标低置信度、更新 prompt、修代码、无需处理 |
| reviewer_note | 简短说明，不复制私有品牌原文 |

## 5. 通过 / 不通过标准

### 5.1 页面级通过

一个抽样页同时满足以下条件，记为页面级通过：

- 页码 / slide 锚点正确。
- 主要文字内容被转写，阅读顺序不影响理解。
- 表格、图片、图表、小字、OCR 风险如未读清，已明确标为低置信度或需要复核。
- 关键事实能追溯到该页或相邻上下文。
- 没有把资料未提供的信息写成确定事实。

### 5.2 事实级通过

一条事实候选或 Wiki 条目同时满足以下条件，记为事实级通过：

- 内容可在来源锚点中找到直接依据，或明确标注为 `AI 结构化转述，待确认`。
- 数字、单位、时间、对象、适用范围没有被改写错。
- 多来源冲突时保留冲突状态，不自动合并成单一结论。
- 没有冒充 `已品牌确认`。

### 5.3 批次通过

一个资料包可作为 90% 准确性证据，必须同时满足：

- 页面级通过率 >= 90%。
- 事实级通过率 >= 90%。
- P0 问题数为 0。
- P1 问题已进入复核队列，且不会被提升为长期可靠知识。
- 所有未读清的图片、表格、小字、OCR 区域已被标注为低置信度或需要复核。

通过率计算：

```text
页面级通过率 = 页面级通过数量 / 可判断抽样页数量
事实级通过率 = 事实级通过数量 / 可判断抽样事实数量
```

`无法判断` 不计入分母，但必须说明原因。不能用大量 `无法判断` 稀释失败率；如果 `无法判断` 超过抽样量的 15%，本批次不能作为 90% 准确性证据。

### 5.4 不通过条件

出现以下任一情况，本批次不通过：

- 任意 P0 问题。
- 页面级或事实级通过率低于 90%。
- 高风险页面未被抽样。
- 低置信度区域被当成确定事实入库。
- 资料未提供的信息被编造成品牌事实。
- 真实品牌私有内容被复制进正式 docs、examples、prompts、schemas 或 README。

## 6. 严重度定义

| 严重度 | 定义 | 处理 |
|---|---|---|
| P0 | 编造事实、冒充品牌确认、泄露私有内容、版本混淆导致错误结论 | 立即判不通过，修复后重新抽样 |
| P1 | 关键事实错读、关键页漏读、表格核心列丢失、低置信度未暴露 | 阻止入库或进入复核队列 |
| P2 | 局部信息遗漏、非关键顺序错误、辅助图说明不足 | 记录并排期修复 |
| P3 | 格式、措辞、非关键可读性问题 | 不影响通过率，可后续优化 |

## 7. 图片 / 表格 / 小字 / OCR 处理规则

### 图片和图表

- 能读出明确文字或图例时，必须保留来源锚点。
- 只能看出大概主题但无法确认细节时，标为低置信度，不写成事实。
- 无法读取图片内容时，记录为需要人工复核或更换引擎，不得编造图中结论。

### 表格

- 关键表格应保留行列关系、表头、单位、备注和来源页。
- 表格被转成散文后如果丢失数字对应关系，记为 P1 或 P2，取决于是否影响关键事实。
- 复杂表格可先保留 `structured_table` 或低置信度说明，不强行美化。

### 小字和脚注

- 涉及限制条件、适用范围、时间、平台规则、风险提示的小字，按关键内容处理。
- 小字不可读时必须暴露，不得默认忽略。
- 如果主文结论和脚注限制冲突，进入复核队列。

### OCR / 扫描 / 长图

- OCR 页必须检查错字、断行、阅读顺序和漏块。
- OCR 不稳定时，本页不能作为确定事实来源，只能作为待复核线索。
- 长图如果无法稳定分页，应记录截图区域或段落 anchor，并说明边界不稳定。

## 8. 不允许编造的红线

以下内容不得由 AI 猜测、补全或美化成事实：

- 品牌确认结论。
- 产品功效、配方、检测、合规和适用范围。
- 价格、预算、销量、ROI、渠道政策、激励金额和平台数据。
- 竞品名称、攻击性判断、市场份额和排名。
- 时间线、版本优先级、最终决策人和审批状态。
- 资料中没有出现的因果关系、策略意图和业务承诺。
- 图片、图表、小字或 OCR 未读清时的具体结论。

允许的表达只有三类：

- `已从来源资料提取`：来源锚点中明确出现。
- `AI 结构化转述，待确认`：对来源内容做结构整理，但不新增事实。
- `待补充` / `待确认` / `资料未提供`：来源没有足够依据。

## 9. 最小验收输出

每次质量抽样至少留下三类证据：

1. 私有测试目录中的逐项 `quality_sampling_log.md` 或表格。
2. 正式或匿名汇总中的通过率、样本量、P0/P1 数量和剩余限制。
3. 若发现问题，复核队列或修复任务中能追踪到对应 source anchor。

推荐汇总格式：

```text
资料包：匿名批次 ID
总页数：N
抽样页数：N
抽样事实数：N
页面级通过率：N%
事实级通过率：N%
P0 / P1 / P2 / P3：0 / N / N / N
是否可作为 90% 准确性证据：是 / 否
剩余限制：...
```

如果该批次通过，它只能证明当前资料包、当前 source engine 和当前 Structured Wiki 输出达标；不能自动证明所有未来资料包都达标。
